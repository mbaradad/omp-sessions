Plans for your coding agents.

Switchyard plans and supervises coding agents of any harness Agent Orchestrator (AO) can run: Claude Code, Codex, oh-my-pi, OpenCode and the rest. AO runs each one in its own git worktree and keeps it going with no window open; Switchyard adds the plans, and keeps the same sessions in VS Code, the terminal and Hermes Agent.

The idea

One thin layer. The same AO sessions everywhere.

AO runs and tracks the sessions: it starts the agent, gives it a worktree, keeps it alive, follows its pull requests, runs the orchestrator, and serves a phone app and a dashboard. Switchyard doesn't rebuild any of that. It plans the work, and keeps VS Code, the terminal and Hermes looking at, and steering, the same AO sessions.

Sessions never depend on the planner or on a client: if the planner is down, running sessions keep going and queued work waits. What runs where.

Attach from any window

Any number of VS Code windows, terminals and Hermes pages can open the same session. Late arrivals get the full transcript and any open question.

Never silently stuck

When an agent asks something, the session shows needs input in every client, a notification fires, and answering in one place answers it everywhere.

Resumable after anything

Stopped sessions keep their transcript and resume on it, and a session whose host or machine died is resumed from it; a turn that was cut short is lost. Sessions you started in a harness's own terminal aren't adopted.

Any harness

Your agent, whichever harness.

Switchyard runs any harness AO can run in chat mode: Claude Code, Codex, OpenCode, oh-my-pi (omp) and the others on AO's list. oh-my-pi is one of them, not the product's premise. switchyard harnesses shows what AO offers, whether each is logged in, and which one a new session gets and why.

Whatever AO lists

The candidates are AO's chat harnesses with the login status AO reports. Every client picks the same way, including the queued and scheduled tasks the planner starts and Hermes kanban cards. A harness AO can't chat with, or can't start on this machine, is refused with the list.

How one is chosen

  1. The one you ask for: new --harness, a task's or lane's option, the Hermes tool or board, VS Code's pick.
  2. Switchyard's default: config set harness, or switchyard.defaultHarness.
  3. The AO project's worker harness.
  4. AO's default: the only authorized one; with several, omp if it is one of them, else the most used.

What is omp-only

Plan mode, the live permission gate behind Ask and Edits, /undo and /redo checkpoints, the todo mirror, the VS Code language-tools bridge, extra omp flags and the default model of config set model. Other harnesses get Ask, Edits and Auto as AO's approval modes and their models from AO's catalog. Asking another harness for an omp-only feature says so instead of failing.

Hermes, the orchestrator and VS Code

Give it a goal. Review the pull requests.

With the switchyard plugin, Hermes Agent plans and delegates instead of coding on its own. A high-level task goes to AO's orchestrator for the project; the orchestrator splits it into worker sessions and has their pull requests reviewed, and you review the result in VS Code.

  1. Hermes

    Hand over the goal

    In a chat or from a kanban card, Hermes gives the project's orchestrator a goal (switchyard_orchestrator_submit), or starts one session for one concrete task. It starts on demand and is reused.

  2. AO

    Workers and pull requests

    The orchestrator splits the goal into worker sessions, each in its own worktree on the project's worker harness, steers them, and has their pull requests reviewed. AO tracks CI and review state.

  3. VS Code

    Review where you work

    Hermes tells the chat when the orchestrator finishes or needs you. The Orchestrators view lists its workers with their pull requests, and Review Pull Request opens every file in VS Code's diff editor.

Steer it from anywhere

Give it a task, steer a turn in progress, answer its question, change its harness, model, rules or permissions and restart it, from Hermes, the terminal (switchyard orchestrator …) or VS Code.

Pull requests are AO's

Switchyard shows AO's PR data (state, CI, review decision, conflicts, files) and acts through AO. It rebuilds none of AO's behaviour.

One command to review

switchyard vscode <session> --review, or Review PR in VS Code on the Hermes page, opens the session's chat and its pull request review in VS Code.

Plan and delegate from any chat or board.

Install

One command, every profile.

From VS Code, run Switchyard: Install Hermes Plugin… and pick the profiles (or switchyard hermes install --all-profiles). Or install it with Hermes, straight from GitHub:

$ hermes plugins install mbaradad/switchyard/integrations/hermes/switchyard --enable

After installing

Turn the kanban lane on in one profile with hermes switchyard lane on. In Hermes Desktop, switch the page on under Capabilities → Plugins (Desktop connected to Hermes on another machine: add it there with Install from Git first). From Hermes Console on Android, comment @switchyard on a card to hand it to the lane and answer questions in the comments; chats and /switchyard work too. Setup guide · Hermes guide.

The planner

Queue it tonight. Read the results tomorrow.

The Switchyard planner holds the plans: tasks with subtasks, dependencies between sessions, a queue per session and start times. It sends a task to AO when its dependencies are done, a slot is free and its start time has come, with no client open.

Tasks1/2 running · 2 waiting

Tasks with subtasks

Write Title :: step; step, drag to reorder (also between sessions), or press Alt+Enter in the chat to queue instead of send.

Dependencies

A task can wait for other sessions and starts by itself when every parent is done or skipped. A failed parent keeps it blocked until you retry or skip it; cycles are refused, and the board draws the graph.

Per-task options

Harness, model, thinking level, fresh context, 1–5 retries with backoff and a time limit. The planner applies them task by task.

Scheduled starts

Start a queue at 22:00, at 2026-11-08 07:30, or in +2h.

One global limit

Queues across all sessions share one concurrency limit. Waiting tasks start as slots free up, and planned work continues once the planner runs again after a reboot.

Holds and budgets

Queued work is held, not failed, while a provider's rate or usage limit is in force, and starts at the reset. Spend budgets cap what planner tasks spend per rolling hour, day or week.

A failure pauses the queue. A task cut short by a crash or reboot is marked interrupted and waits for you: it never reruns unattended.

Feels like part of VS Code, because it is.

Native views, native diffs, your theme's colors. The agent works in AO's sessions; VS Code shows you what it did, what's next in the queue and the pull requests it opened.

Chat

Open a session in an editor tab or the side bar, or drag the Chat view to the secondary side bar next to your code. Replies stream in; tool calls become cards with live durations.

  • file:line links open in the editor; symbol links resolve through this window
  • Inline diffs with word-level highlights. Click a line to jump there
  • @ for files, / for commands, ! for a shell command
  • Paste or drop images and any file: PDFs, docs, archives
  • Edit & resend from any prompt; Enter steers while the agent works

Diffs & checkpoints

See every change. Undo any of them.

On omp sessions, Switchyard's omp extension snapshots each file before and after every edit, so reviews are exact and reverts are safe, even for changes made while you were away. On any harness, the pull request is the review (below).

  • Diff opens VS Code's own diff editor for any tool call; Revert restores the file to before it
  • N files changed opens a multi-file review of everything the session touched
  • A π badge in the Explorer and changed-line markers in open editors
  • Undo and redo a turn, files and conversation together (omp only)

Pull requests & the orchestrator

AO's pull requests and orchestrator, in your editor.

Pull request review

A Pull Requests view lists each session's PRs with CI, review decision, failing checks and unresolved comments. Review Pull Request opens every file in the multi-file diff editor, base against head, with review comments as threads and Ask the Agent to Address This Comment. Merge, ask AO's reviewer, resolve threads or let AO fix CI and comments: AO does it.

One node per AO project with an orchestrator: its state, harness and last reply, the question it waits on, its workers with PR chips (#12 open · CI passing · approved) and its settings. Give Orchestrator a Task…, steer it, configure it (harness, model, rules, worker harness) and restart it from there or the Command Center.

Open it from outside

Permission modes, checkpoints and the terminal UI

More control, fewer surprises.

Ask, Edits and Auto work on any harness. Plan mode, the gate that holds with VS Code closed, /undo checkpoints and omp's terminal UI are omp-only, and marked as such.

File edits go through; commands and other tools ask.

Shift+Tab cycles modes in the composer

Permission modes

Switch live from a chip in the chat, even mid-turn. On other harnesses Ask, Edits and Auto are AO's approval modes, and a harness that can't run a mode refuses it. On omp, Switchyard's extension enforces the mode inside the session, so it still applies with VS Code closed; Plan is omp-only.

Checkpoints (omp)

On omp sessions every prompt is a restore point. Roll back the files and the conversation to any of them, or undo and redo the last turn.

And the rest

The whole toolbox, wired in.

Git worktrees & Best-of-N

Every session runs in its own AO worktree on a branch ao/<session>/root, so parallel sessions never overwrite each other. Start one on a branch you pick, or run the same task in N worktrees and keep the best. Compare with base, merge into the main checkout, or remove it all in one step.

VS Code bridge

On omp sessions, a session can use this window's language features: symbols, definitions, hover and diagnostics of open files.

Doctor

A health report with one-click fixes: AO or the planner not running, missing or logged-out agents, Switchyard's omp extension missing or out of date, and Hermes: the plugin in each profile, notifications and the kanban lane.

Command Center

Ctrl/Cmd+Alt+P: a searchable, grouped index of every command, orchestrator and pull request ones included.

Code actions

Fix with Agent on problems, Explain with Agent on a selection, Fix Failed Command after a terminal error.

Source Control

Organization

Nested groups with colors and icons; priority, pin, archive and tags per session, from the tree or the board.

Sessions your way

New Session with Options: model, thinking level, permission mode and a goal, plus plan-first, advisor and extra flags for omp. A default harness, model and mode for every client, and a toggle between this workspace's sessions and all of them.

A skill for other agents

switchyard skill install teaches Claude Code, Codex, omp and others to start, queue or schedule a session, wait for it, read its report, answer its questions and follow up.

Built for scripts

Laptop or server

Your computer or a server. Same steps.

Agent Orchestrator, the planner, your agents' harnesses, every session and Hermes run on the machine with your code. Only where you reach them from changes.

All on one computer

AO, the planner, a harness and Hermes on the same Mac or Linux machine, with a local VS Code window or just the terminal. Hermes Desktop in local mode picks up the Switchyard page from the plugin.

A workstation or server

Phone & Hermes from anywhere

Pair AO's phone app over Tailscale, and connect Hermes Desktop or Hermes Console to the machine's Hermes. AO's desktop app can also use the machine's AO as a remote host. Answer and approve while you're away.

Check everything with switchyard status, Switchyard: Run Doctor and hermes switchyard status. On Windows, run it in WSL 2. Setup guide, step by step.

    Claude Code on a headless AO built from source also needs AO's Claude ACP runtime: the setup guide says how.

    Switchyard

    The VS Code extension, from the Marketplace or Open VSX (over Remote-SSH, install it on the SSH host). Open a folder and press + in the Switchyard Sessions view.

    Or just the command, with Node 22+: npm install -g the switchyard package from the latest release (then switchyard omp-extension install if you use omp). Check with switchyard status and switchyard harnesses. On a server or with Hermes? See your setup.

FAQ

Questions, answered.

Anything else? Open an issue on GitHub.

What is Agent Orchestrator (AO)?

AO is the engine underneath. It runs coding agents on the harness you pick, gives each session its own git worktree and branch, keeps it alive with no client open, tracks its pull requests, CI and reviews, runs the project's orchestrator agent, and serves a phone app and a dashboard. Switchyard is a layer on top of it, not a replacement.

Do I need omp?

No. oh-my-pi is one of the harnesses AO can run; any authorized one works. With several authorized and nothing chosen, AO's default is omp if it is one of them. Only a few features are omp-only: Plan mode, the permission gate that holds with VS Code closed, /undo checkpoints, the todo mirror, the language-tools bridge and extra omp flags.

Which harnesses work?

AO's chat harnesses: Claude Code, Codex, OpenCode, omp, pi and the others AO lists. switchyard harnesses shows them with their login status and the one a new session gets. A harness AO can't chat with, or can't start on this machine, is refused with the list.

What does Switchyard add over AO's own app?

AO runs and tracks the sessions and has its own desktop app, dashboard and phone app. Switchyard adds the planner (task graphs, queues per session, scheduled starts, usage holds, budgets and a concurrency limit, which run with no client open) and puts the same sessions in VS Code (chat, diffs, board, pull request review, the orchestrator), the switchyard command and a Hermes plugin. AO's own dashboard also opens in VS Code and on the Hermes page.

What does it cost?

The extension is free and MIT-licensed. You bring your own agent harness and model provider, and pay that provider for model usage as you would anywhere else. The usage dashboard and the status bar show what your sessions spend.

Is my data local?

Yes. No telemetry. Session state lives in ~/.switchyard/ and AO's data in ~/.ao/data/ on the machine that runs the sessions, and transcripts stay with the harness (omp's are in its own sessions folder). Clients talk to AO and the planner on that machine; the agent talks to the model provider you configured.

What do I need?

Agent Orchestrator and a signed-in harness on the machine where sessions run, plus either VS Code 1.100 or newer with the extension (on that machine, or connected to it over Remote-SSH), or Node 22+ for the standalone switchyard command.

Do I need Remote-SSH?

No. A local window works the same way: AO runs the sessions on your computer and they survive closing VS Code. Remote-SSH only puts them on another machine, and the terminal command needs no VS Code at all. The setup guide covers both.

Which platforms are supported?

Linux and macOS, as your own computer or as a server you reach over SSH. On Windows, run AO and Switchyard in WSL 2 (VS Code in a WSL window, Tailscale on the Windows side).

What happens when my machine reboots?

The agent processes stop, and AO resumes a session from its transcript when you next use it. The planner comes back as a login service and planned work continues; tasks that were running wait as interrupted. Nothing runs twice. Closing VS Code, sleeping or disconnecting doesn't stop anything.

I used omp Sessions. How do I migrate?

Switchyard is a new extension and command (mbaradad.switchyard, switchyard) and doesn't read the old state by itself. switchyard migrate imports your default model and mode, the concurrency limit and your groups and board lanes: a dry run until --apply, with a backup of ~/.omp/vscode first. No session is migrated: the dry run lists each old one with the omp --resume <id> command that continues it, and its unfinished queued tasks. Then you can remove the old extension and the omp-sessions command.

Can I still use omp's terminal UI?

Yes, for omp sessions. switchyard attach chats with any session in the terminal, and the TUI switch opens omp's own terminal UI on an omp session. Sessions you started in a harness's own terminal aren't adopted; continue those there (for omp, omp --resume).

Can I use the Hermes plugin without VS Code?

Yes. The plugin drives the switchyard command, which installs without VS Code: npm install -g the package from the latest release on the machine that runs Hermes, then install the plugin with switchyard hermes install or hermes plugins install mbaradad/switchyard/integrations/hermes/switchyard --enable.

Does it work with Hermes Console on Android?

Yes, through kanban and chats. Comment @switchyard on a card to hand it to the lane; the card shows the session's status and result, blocks with its question, and your comments answer that question or reach the session as messages. Approvals are answered on AO's phone app or the Switchyard page, not in comments. In chats, Hermes uses the Switchyard tools and gets the "finished" and "needs you" notes, and /switchyard gives a summary. Console doesn't show plugin pages, so for every session at once use AO's phone app.

Are all file changes tracked for diffs and revert?

On omp sessions, changes made through omp's file-editing tools are snapshotted before and after every call; changes made through shell commands (for example sed -i or code generators) are not. Whatever the harness, a session's pull request is reviewable in VS Code.
