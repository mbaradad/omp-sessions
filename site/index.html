A task server for your coding agents.

omp Sessions runs oh-my-pi sessions as background jobs on your machine. Give each one a queue of tasks, schedule when it starts and cap how many run at once. Sessions keep working when you close VS Code or drop SSH, and the server starts queued work again after a reboot. Drive it all from VS Code, the terminal, your phone or Hermes Agent.

Why a server

More than omp in tmux.

tmux keeps one omp process alive. omp Sessions keeps the work moving: each session runs in its own detached host, the omp-vs server queues, schedules and limits them, and any window, script or agent picks them up where they are.

Attach from any window

Any number of VS Code windows can open the same session. Late arrivals get the full transcript, open dialogs and in-flight tools.

Never silently stuck

When omp asks something, the session shows needs input in the tree and status bar, and a notification fires if the chat isn't visible.

Resumable after anything

Stopped sessions keep their transcript and resume on it. A crashed host shows as stopped and resumes cleanly. You can even adopt an omp session started in a terminal.

The server: queue & scheduler

Queue it tonight. Read the results tomorrow.

Each session's queue belongs to its background host, which feeds tasks to omp one after another whenever the session is idle. Scheduled queues start on time, and the omp-vs server launches waiting work as slots free up, even for stopped sessions. Nothing needs to stay open.

Tasks2/3 running · 5 waiting

Tasks with subtasks

Write Title :: step; step, drag to reorder (also between sessions), or press Alt+Enter in the chat to queue instead of send.

Per-task options

Model, thinking level, fresh context, 1–5 retries with backoff and a time limit. The host applies them task by task.

Scheduled starts

Start a queue at 22:00, at 2026-11-08 07:30, or in +2h.

One global limit

Queues across all sessions share a concurrency limit that the hosts enforce themselves. The omp-vs server starts waiting sessions as slots free up, even after a reboot.

A failure or an interruption pauses the queue. Tasks interrupted by a crash are never rerun unattended.

Phone app & HTTP API

Your sessions, in your pocket.

Run omp: Connect Phone… and scan the QR code. The omp-vs server serves a small web app you can add to your home screen, on the same machine as your sessions.

  • See what's working, waiting for you, or done
  • Follow a session live; prompt, steer or queue
  • Approve or deny tool calls and switch the permission mode
  • Start a session in a recent folder, or queue it for later

Over Tailscale (free, encrypted), behind Tailscale Serve or your own HTTPS proxy (handy in WSL), or your Wi-Fi, protected by a token. The same JSON + Server-Sent Events API is documented for your own apps and servers.

Hermes Agent plugin

Hermes plans the work. omp does the coding.

With the omp-sessions plugin, Hermes schedules omp sessions instead of coding on its own. It starts them in the right folder, project or board, hears back when they finish, and runs kanban cards as omp sessions.

Your setup

Your computer or a server. Same steps.

omp, the omp-vs server, every session and Hermes run on the machine with your code. Only where you open the windows from changes.

All on one computer

A local VS Code window, with omp, the server and Hermes on the same Mac or Linux machine. Hermes Desktop in local mode picks up the omp Sessions page from the plugin; your phone joins over Tailscale.

A workstation or server

VS Code connects with Remote-SSH and the extension runs there, next to your code and Hermes. Close the laptop: sessions, queues and the kanban lane keep going. Hermes Desktop connects in remote mode; add the page once with Install from Git.

Windows with WSL 2

Run omp and Hermes in WSL and open VS Code in a WSL window. Tailscale usually runs on Windows, so the phone connects through tailscale serve; Connect Phone walks you through it.

omp-vs server install keeps the server running as a systemd or launchd service; Hermes and the plugin work without VS Code open. Check it all with omp: Run Doctor and hermes omp status. Setup guide, step by step.

FAQ

Questions, answered.

Anything else? Open an issue on GitHub.

What do I need?

VS Code 1.100 or newer, and omp installed on the machine where the extension host runs: your computer for local folders, the server for Remote-SSH. The optional omp-vs command runs on Node 22+ from your PATH, or on VS Code's own runtime.

What does it cost?

The extension is free and MIT-licensed. You bring your own omp and model provider, and pay that provider for model usage just as you would in omp's terminal UI. The usage dashboard and the status bar show what your sessions spend.

Does it collect any data?

No telemetry. Session state lives in ~/.omp/vscode/ on the machine that runs the sessions, and transcripts stay in omp's own ~/.omp/agent/sessions/. VS Code talks to each session over a local Unix socket; omp talks to the model provider you configured.

Do I need Remote-SSH?

No. A local window works the same way: sessions run in detached processes on your computer and survive closing VS Code. Remote-SSH, WSL or a dev container only put them on another machine. The setup guide covers both.

Which platforms are supported?

Linux and macOS, as your local machine or as the Remote-SSH server, and Windows through WSL 2 (open VS Code in a WSL window). On native Windows, named pipes and .cmd shims are handled, but it's untested.

What happens when my machine reboots?

A reboot stops sessions, but their transcripts stay resumable. Queued work restarts once the omp-vs server runs again; omp-vs server install starts it at login. Closing VS Code, sleeping or disconnecting doesn't stop anything.

Can I still use omp in the terminal?

Yes. omp-vs attach chats with a session in the terminal, the TUI switch opens omp's own terminal UI on the session, and Resume omp Transcript in Background adopts sessions you started in a terminal.

Can I use the Hermes plugin without VS Code?

Hermes installs the plugin from GitHub (hermes plugins install mbaradad/omp-vscode/integrations/hermes/omp-sessions), but the plugin drives omp-vs, which ships with the extension. Install the extension once on the machine that runs Hermes and run omp: Install omp-vs Command; after that, VS Code doesn't need to stay open.

Does it work with Hermes Console on Android?

Yes, through kanban and chats. Comment @omp on a card to hand it to omp; the card shows the session's status and result, blocks with omp's question (Console notifies you), and your comments answer that question or reach the session as messages. In chats, Hermes uses the omp tools and gets the "finished" and "needs you" notes, and /omp gives a summary. Console doesn't show plugin pages, so for every session at once use the omp phone app.

Are all file changes tracked for diffs and revert?

Changes made through omp's file-editing tools are snapshotted before and after every call. Changes made through shell commands (for example sed -i or code generators) are not.
