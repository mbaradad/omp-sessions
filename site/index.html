Plans for your coding agents.

Switchyard plans work for oh-my-pi coding agents and hands it to Agent Orchestrator (AO) to run. Write tasks with subtasks and dependencies, queues per session, scheduled starts and a limit on how many run at once; AO runs each task as an omp session in its own git worktree. Drive it from the terminal, VS Code, Hermes Agent or AO's phone app.

Why a planner

More than omp in tmux.

tmux keeps one omp process alive. Switchyard keeps the work moving: AO runs each session in its own git worktree and keeps it alive with no client open, the Switchyard planner queues, schedules and limits them, and any window, script or agent reaches the same sessions.

Attach from any window

Any number of VS Code windows can open the same session. Late arrivals get the full transcript, open dialogs and in-flight tools.

Never silently stuck

When omp asks something, the session shows needs input in the tree and status bar, and a notification fires if the chat isn't visible.

Resumable after anything

Stopped sessions keep their transcript and resume on it. A session whose host or machine died is resumed from omp's transcript; a turn that was cut short is lost. Sessions you started in omp's own terminal UI aren't adopted: continue those with omp --resume.

The planner: queue & scheduler

Queue it tonight. Read the results tomorrow.

The Switchyard planner holds each session's queue and sends a task to AO when its dependencies are done, a slot is free and its start time has come. Scheduled queues start on time. Nothing needs to stay open.

Tasks2/3 running · 5 waiting

Tasks with subtasks

Write Title :: step; step, drag to reorder (also between sessions), or press Alt+Enter in the chat to queue instead of send.

Per-task options

Model, thinking level, fresh context, 1–5 retries with backoff and a time limit. The planner applies them task by task.

Scheduled starts

Start a queue at 22:00, at 2026-11-08 07:30, or in +2h.

One global limit

Queues across all sessions share one concurrency limit. The planner starts waiting tasks as slots free up, and planned work continues once the planner runs again after a reboot.

A failure pauses the queue. A task cut short by a crash or reboot is marked interrupted and waits for you: it never reruns unattended.

Same sessions. No VS Code required.

The switchyard command drives everything without VS Code: sessions, queues, schedules, models and the planner, over plain SSH or from scripts. Install it from VS Code (Switchyard: Install switchyard Command) or, without VS Code, with npm install -g from the GitHub release.

Hermes Agent plugin

Hermes plans the work. omp does the coding.

With the switchyard plugin, Hermes schedules omp sessions instead of coding on its own. It starts them in the right folder, project or board, hears back when they finish, and runs kanban cards as omp sessions.

In Hermes

Schedule sessions from any chat or board.

  • 14 tools to start, queue or schedule a session, check it, answer it, steer it, switch its model and stop it, and to check the server
  • The chat that started a session gets a message when it finishes or needs you
  • Kanban cards assigned to omp run as omp sessions, one group per board, with an optional model per board; the reply becomes the card's result, and trusted comments answer omp or steer it
  • Approvals stay with you: comments and the agent can't answer them unless you allow it
  • Open any session, or its project, in VS Code from the page

Install

One command, every profile.

From VS Code, run Switchyard: Install Hermes Plugin… and pick the profiles (or switchyard hermes install --all-profiles). Or install it with Hermes, straight from GitHub:

$ hermes plugins install mbaradad/omp-sessions/integrations/hermes/switchyard --enable

Then turn the kanban lane on in one profile with hermes switchyard lane on. In Hermes Desktop, switch the page on under Capabilities → Plugins (Desktop connected to Hermes on another machine: add it there with Install from Git first). From Hermes Console on Android, comment @omp on a card to hand it to omp and answer its questions in the comments; chats and /switchyard work too. Setup guide · Hermes guide.

Your setup

Your computer or a server. Same steps.

omp, Agent Orchestrator, the planner, every session and Hermes run on the machine with your code. Only where you reach them from changes.

All on one computer

omp, AO, the planner and Hermes on the same Mac or Linux machine, with a local VS Code window or just the terminal. Hermes Desktop in local mode picks up the Switchyard page from the plugin.

A workstation or server

Everything runs there; reach it with ssh and switchyard, or VS Code Remote-SSH. Close the laptop: sessions, queues and the kanban lane keep going. No VS Code on the box? Install the command from the release.

Phone & Hermes from anywhere

Pair AO's phone app over Tailscale, and connect Hermes Desktop or Hermes Console to the machine's Hermes. Answer and approve while you're away.

The planner installs itself as a systemd or launchd login service the first time a client starts it, so queued and scheduled work comes back after a crash or reboot. Check everything with switchyard status, Switchyard: Run Doctor and hermes switchyard status. On Windows, run it in WSL 2. Setup guide, step by step.

FAQ

Questions, answered.

Anything else? Open an issue on GitHub.

What do I need?

omp on the machine where sessions run, plus either VS Code 1.100 or newer with the extension (on that machine, or connected to it over Remote-SSH), or Node 22+ for the standalone switchyard command.

What does it cost?

The extension is free and MIT-licensed. You bring your own omp and model provider, and pay that provider for model usage just as you would in omp's terminal UI. The usage dashboard and the status bar show what your sessions spend.

Does it collect any data?

No telemetry. Session state lives in ~/.switchyard/ on the machine that runs the sessions, and transcripts stay in omp's own sessions folder. Clients talk to AO and the planner on the machine; omp talks to the model provider you configured.

Do I need Remote-SSH?

No. A local window works the same way: AO runs the sessions on your computer and they survive closing VS Code. Remote-SSH only puts them on another machine, and the terminal command needs no VS Code at all. The setup guide covers both.

Which platforms are supported?

Linux and macOS, as your own computer or as a server you reach over SSH. On Windows, run omp and Switchyard in WSL 2 (VS Code in a WSL window, Tailscale on the Windows side).

What happens when my machine reboots?

Sessions stop, but AO resumes a session from omp's transcript when you next use it. The planner comes back as a login service and planned work continues; tasks that were running wait as interrupted. Nothing runs twice. Closing VS Code, sleeping or disconnecting doesn't stop anything.

Can I still use omp in the terminal?

Yes. switchyard attach chats with a session in the terminal, and the TUI switch opens omp's own terminal UI on the session. Sessions you started in omp's own terminal aren't adopted; continue those with omp --resume.

Can I use the Hermes plugin without VS Code?

Yes. The plugin drives the switchyard command, which installs without VS Code: npm install -g the package from the latest release on the machine that runs Hermes, then install the plugin with switchyard hermes install or hermes plugins install mbaradad/omp-sessions/integrations/hermes/switchyard --enable.

Does it work with Hermes Console on Android?

Yes, through kanban and chats. Comment @omp on a card to hand it to omp; the card shows the session's status and result, blocks with omp's question (Console notifies you), and your comments answer that question or reach the session as messages. Approvals are answered on AO's phone app or the Switchyard page, not in comments. In chats, Hermes uses the omp tools and gets the "finished" and "needs you" notes, and /switchyard gives a summary. Console doesn't show plugin pages, so for every session at once use AO's phone app.

Are all file changes tracked for diffs and revert?

Changes made through omp's file-editing tools are snapshotted before and after every call. Changes made through shell commands (for example sed -i or code generators) are not.
