# Changelog

## 0.6.0

- **The terminal command is now `omp-sessions`** (was `omp-vs`), with env vars `OMP_SESSIONS_*` and the Hermes plugin setting `omp_sessions`. The extension replaces the old launcher and service (`omp-sessions.service`, launchd `dev.omp.sessions-server`) automatically; running sessions keep going. On Windows, add `%LOCALAPPDATA%\omp-sessions` to PATH.
- **Permission modes**: Ask / Edits / Plan / Auto, switchable live from the chat footer, **Shift+Tab**, `/mode`, `/plan`, *Set Permission Mode…* and `omp-sessions mode`. omp now always runs with `--approval-mode always-ask` and the session host answers its approval prompts by mode, so the mode holds with VS Code closed and switching resolves approvals already waiting. Plan mode refuses file edits and asks the model for a plan. The mode is remembered across resumes; new sessions start in omp's `tools.approvalMode`, else Auto. Replaces the wizard's *Auto-approve* flag and the approval-mode restart setting.
- **Checkpoints**: undo any turn from the prompt's undo button, *Undo last turn* or `/undo` — the conversation rewinds to before that prompt and the files omp's edit tools changed go back; *Redo* / `/redo` restores both.
- **Voice** (`/voice`, mic button): omp's realtime voice with a live transcript, level meter, mute and end; `omp.voice.name` picks the voice.
- **Terminal UI**: *Continue Session in omp's Terminal UI* (chat header button, `/tui`) opens the session in omp's own TUI beside the chat and hands it back to the background host when the terminal closes.
- **Chat footer**: starred models pinned on top of the model picker, tokens per second, and the provider usage limit when omp reports it.
- **Phone app and HTTP API**: *Connect Phone…* turns on remote access in the `omp-sessions` server (Tailscale, local network or localhost) and shows a QR code. The phone web app (installable to the home screen) lists every session by status, follows one live, prompts or steers it, answers approvals and questions, switches its permission mode, stops or resumes it, and starts or queues new sessions in recent folders. The token-authenticated JSON + Server-Sent Events API behind it is documented in `docs/REMOTE-API.md` for other apps and servers. *Disable Remote Access*, *Rotate Remote Access Token*, and `omp-sessions remote on|off|status|qr|rotate`.
- Remote access behind Tailscale Serve or any HTTPS proxy: `omp-sessions remote on --bind localhost --url https://<machine>.<tailnet>.ts.net` (or *Connect Phone… → Behind Tailscale Serve or an HTTPS proxy*) puts that URL in the pairing link and accepts writes from its origin, so the phone talks HTTPS with a real certificate. In WSL, where Tailscale runs on Windows, *Connect Phone…* recommends it and explains the one Windows command.
- **Hermes Agent plugin** (*Install Hermes Plugin…*, `omp-sessions hermes install`): native `omp_session_*` tools for Hermes agents, including start, queue, schedule (`at`), status, wait, answer, steer and stop, picking a folder by path, known project or board. Hermes gets a message in the chat when a session it started finishes or needs input. A kanban lane runs cards assigned to `omp` as omp sessions, in the card's workspace or the board's folder, with one omp group per board. Results, questions (`needs_input` blocks) and failures go back to the card, and dependent cards chain as usual. Docs: `docs/HERMES.md`.
- **omp Sessions page in Hermes**: the plugin adds a page to the left sidebar of the Hermes web dashboard and Hermes Desktop (opt-in under *Capabilities → Plugins*): sessions in columns (needs you, working, queued and scheduled, done, stopped) with filters by board, group and project; a detail panel to answer questions and approvals, follow up, switch the mode or stop; *New session* (now, queued or at a time, in a folder, project or board); and a Boards view with each board's lane settings and linked cards.
- The Hermes plugin also installs straight from GitHub: `hermes plugins install mbaradad/omp-vscode/integrations/hermes/omp-sessions --enable`. `npm run hermes:catalog` prints its Hermes plugin-catalog entry (see `docs/PUBLISHING.md`).
- omp Sessions page polish: in Hermes Desktop the primary button uses Desktop's accent color, and columns wrap in a narrow window instead of scrolling sideways (empty columns take less room). Done shows the 24 most recent sessions, then *Show N more*. Long titles show in full on hover. Replies render tables, horizontal rules, italics, and code inside bold. Boards in the lane are listed first, and a time from a slightly fast clock shows as "just now" instead of "any moment". Desktop keeps its own copy of the page, so the page says when it is older than the plugin on the Hermes it talks to, and how to update it. `docs/HERMES.md` explains installing the Desktop half when Desktop runs against a remote backend.
- **Open in VS Code** from the omp Sessions page (detail panel → *VS Code*) and `omp-sessions vscode <session>`: the session's chat opens in the VS Code window last used on omp's machine, also a Remote-SSH window on a laptop (the link opens the session's folder over that window's remote authority; the window takes the recorded request when it gains focus). Hermes Desktop, which opens only web links, goes through a small redirect page of the dashboard in the browser. The extension also handles `vscode://mbaradad.omp-sessions/open?session=<id>`.
- `/omp` in a chat is now a short summary (what needs you, what is working, queued, done) that fits a phone, and `/omp take <card> [board]` (`hermes omp take` in a terminal) hands an existing kanban card to omp. That works from clients whose assignee picker lists only Hermes profiles, such as Hermes Console on Android; `docs/HERMES.md` describes what Console shows.
- **Kanban comments reach omp**: a comment on a card the lane runs answers omp's open question (the lane then unblocks the card) or arrives in the session as a message, a follow-up while omp works; the lane confirms each delivery with a comment. `@omp` in a comment on any card of a lane board assigns the card to omp. With Hermes Console on Android, that makes a card's detail screen a way to hand work to omp, answer it and steer it.
- `hermes omp board … --remove`, clearing a board setting and `hermes omp project --remove` now take effect (they used to be silently ignored).
- `hermes omp status` (and the page's Lane item) shows the kanban dispatcher's last tick and which profile's plugin it reached, and warns when the lane is on in a different profile, when the dispatcher's profile has the lane off, or when no tick has arrived for 3 minutes. It also says whether the last notification was delivered or refused, instead of reading Hermes's consent setting through a private API; with notifications allowed, Doctor reports a refused note as information (the chat that started the session had ended, as with a one-shot `hermes chat -Q`), and the plugin stops retrying such a note after an hour. Sessions started by Hermes tools are tagged `hermes`.
- **Hermes plugin updates itself**: when the extension updates, the copies omp-sessions installed are refreshed in every Hermes profile (Git and catalog installs are left alone); `omp-sessions hermes install` does the same. Only a newer bundled plugin (version, then build) replaces a copy automatically, so editors with different extension versions never downgrade each other, and an install lock in the profile's `plugins/` keeps several windows from racing (staging folders are named so Hermes never loads them, and crashed runs' leftovers are swept). Where the plugin was enabled it is disabled and re-enabled, so the running gateway reloads it in place: no gateway restart, chats untouched; if enabling it again fails twice you're told it was left disabled, with an Enable action. You're told once what changed, and when the dashboard's page backend needs a dashboard restart.
- **Hermes in VS Code**: sessions Hermes started show a **Hermes** chip in the Sessions view and the chat header; kanban-lane sessions show **Hermes · board · card**, with *Open Hermes Card* (the Hermes dashboard's Kanban page, `omp.hermes.dashboardUrl`, forwarded from remote windows) and *Show Hermes Card in Terminal*.
- Hermes integration on more setups: *Open Hermes Card* opens the dashboard Hermes reports running on that machine, at whatever port (`omp.hermes.dashboardUrl` now defaults to empty for that), and offers the terminal view when no dashboard runs; Hermes's Windows home (`%LOCALAPPDATA%\hermes`), `HERMES_HOME` with `~` or a data-dir suffix, `.cmd` launchers, the Windows `omp-sessions` command, per-profile gateways in Doctor, and a cross-process lane lock on Windows. The phone hints use the configured port.
- **omp Doctor checks Hermes**: the plugin in each profile (outdated, disabled, Git install), notifications (`allow_gateway_injection`, a refused note), the kanban dispatcher's last tick, the lane on in several profiles or in one the dispatcher doesn't tick, and whether the plugin finds `omp-sessions`, with one-click fixes.
- `omp-sessions hermes` always runs `hermes -p <profile>`: without a profile flag it used to act on the sticky `hermes profile use` profile instead of the default home. `omp-sessions hermes status` reads each profile's `config.yaml` instead of starting hermes per profile, and reports when notifications aren't allowed.
- **omp-sessions skill for other agents** (*Install omp Sessions Skill for Agents…*, `omp-sessions skill install`): teaches omp, Claude Code, Codex and anything reading `~/.agents/skills` to start, schedule and supervise omp sessions through `omp-sessions`. Copies it installed are refreshed when the extension updates.
- `omp-sessions` for scripts and agents:
  - `new` gains `--json`, `--mode`, `--tag`, `--group`, `--notes` and `--at` (schedule a queued task);
  - `new` returns once the session's host is up, so `omp-sessions wait .` or `show .` right after it finds the session, and `--json` reports its title;
  - `show [--json]` reports the state, waiting question and full last reply;
  - `wait [--timeout] [--json]` exits 0 when idle, 3 on needs input, 4 when stopped;
  - `answer` replies to a waiting question;
  - `projects [--json]`, `sched --json`;
  - `ls --json` includes session tags.
- Sessions Board: columns lay out as a grid again (cards no longer collapse into one row), and card excerpts drop Markdown markup (also in the phone app).
- Opening a session (a chat panel, `omp-sessions attach`, `omp-sessions show`, the phone app or the Hermes page) no longer counts as activity: lists sorted by recent activity don't reorder and "active" times don't reset when you only look.
- Resuming a session right after stopping it no longer leaves it unreachable: the exiting host could delete the new host's socket (seen as a flaky test on macOS).
- *Connect Phone*: the pairing page has **Open in Browser**. In a Remote-SSH window VS Code forwards the port, so the localhost bind (now labeled *The remote machine only*) can be tried in the browser on your computer.
- `omp-sessions server install` no longer leaves the server stopped (the service's server started while the old one still held the socket, and exited), and reinstalling on macOS replaces the loaded agent instead of failing. With the service installed, `omp-sessions server restart`, on-demand starts and the extension's upgrade restarts go through systemd/launchd, so the server stays supervised; a service that doesn't come up within 2 s (say, its unit points at a node that moved) falls back to starting the server directly.
- README rewritten around use cases, with screenshots and graphics; website at <https://mbaradad.github.io/omp-vscode/>.

## 0.5.0

- **`omp-vs` terminal command** (*omp: Install omp-vs Command*): `ls`, `board`, `new` (prompt, or `--task` to queue), `attach` (streaming chat with inline dialogs, Ctrl-C aborts, Ctrl-D detaches), `send [--wait]`, `tail [-f]`, `stop`/`resume`/`rm`/`abort`, `queue …` (add/run/start/pause/retry/done/skip/`at +30m`), `prio`/`color`/`group`/`move`/`archive`, `sched …`, `server …`. Sessions are named by id prefix, title words or `.`; `ls` hides finished sessions unless `--all`.
- **omp-vs server**: a per-user daemon that starts stopped sessions whose queue has runnable work when a concurrency slot frees up (priority + manual order, ranked together with hosts already waiting), so queued work also resumes after a reboot. It stops the sessions it launched once their queue is done and no chat/`attach` is open, backs off exponentially from sessions that die right after launch, and never reruns a task a crash interrupted. The extension installs a stable runtime copy and keeps the server at its version (`omp.server.autoStart`); `omp-vs server install` adds a systemd user unit / launchd agent. *Restart omp-vs Server*, *Show omp-vs Server Log*.
- **Hide Finished Sessions** (eye button in the Sessions view): hides stopped sessions; unread ones stay until seen, and the view header shows how many are hidden.
- Sessions view: *Group Sessions By…* now offers custom groups and status, the new `omp.sortBy` setting backs *Sort Sessions By…*, and the organize/scheduler commands (filter, groups, color, priority, tags, lanes, pin, archive, move, bulk stop/resume/remove, concurrency) appear in the view and context menus.
- Session hosts publish how many people are attached (`viewers`) and when someone last typed (`userActiveAt`).

## 0.4.0

- **Command Center** (`Ctrl/Cmd+Alt+P`): a searchable, grouped index of every omp command — session, task, worktree, queue, git, dashboard, session — plus omp's own CLI features surfaced as VS Code commands (*login, update, setup, plugins, skills, usage, stats, models, cleanse, commit in terminal, git UI, continue in terminal, import Claude/Codex, open docs/config, keyboard shortcuts*). *Fix with omp / Explain / Ask about…* code actions join the existing editor integration; new *Edit with omp* (`Ctrl/Cmd+Alt+E`), *Fix File/Workspace Problems*, *Fix Failed Command*, *Write Tests*, *Add Docs*.
- **Git worktrees**: *New Session in Git Worktree…* (sibling `<repo>.worktrees`, `omp/<task>` branch, any base branch/tag/commit) and *Best-of-N* — the same task in N parallel worktree sessions. Worktrees group under the main repo in the Sessions view; *Compare Worktree Branch with Base*, *Merge into Main Checkout…*, *Open in New Window*, *Remove Worktree and Session*.
- **Sessions Board** (*Open Sessions Board*): a kanban of every session with drag & drop and keyboard moves. Columns by status, swimlane, group, or priority; lanes (Backlog / To Do / In Progress / Review / Done) are editable; one row per project in swimlane mode. Per-card and bulk: priority (P to cycle), color, pin, archive, tags, stop/resume/open, queue progress, cost, last text, unread. A global concurrency counter sits in the header (see below).
- **Organization**: groups (nested, colored, iconed), colors, priorities, pins, archive, and tags on sessions — in the tree (drag & drop, context menus) and the board. Sessions view filters (text, `#tag`, `project:name`), manual sort, and group collapse persist in `organize.json`.
- **Global concurrency scheduler**: queue tasks across all sessions now respect a shared limit (`scheduler.json`, honored by the session host with VS Code closed). Status-bar counter "2/3 running · 5 waiting"; *Set Concurrency…*, *Increase/Decrease*, *Pause/Resume Queued Tasks*. A queued task waiting for a slot shows its position in the tree and on the board.
- **Task queue extensions**: per-task *Options…* (model, thinking, fresh context, retries, timeout), *Duplicate Task*, *Retry Failed Tasks*, and *Schedule Queue Start…* (`HH:MM`, a date, or `+30m/+2h`). The host applies each task's model/thinking/retries.
- **Usage dashboard** (*Usage Dashboard*): sessions, cost, and token trends over a chosen range; *Show Today's Spend* in the status bar; *Search Session History…* across every transcript (open the session, resume, or read the transcript).
- **VS Code bridge**: omp sessions can call this window's language features through a per-session MCP server (`out/mcp.js` → JSONL socket → extension). Symbol links in chat resolve to the right file/line; hover docs and diagnostics are exposed to the model. *VS Code Bridge: Show Status* reports connected windows, the MCP script, and a round-trip probe. Per-session *Session Settings…* toggles skills, tools, and MCP servers (with a tooltip chip when non-default).
- **Doctor** (*Run Doctor*): a report of omp/session health — missing omp, auth problems (no API key / not logged in), outdated hosts, and hosts that died mid-turn — with one-click fixes (*mark stopped*, *resume*, *upgrade host*). *Copy Diagnostics*, *Upgrade Session Host(s)*, *Clean Up File Snapshots*. Crashed sessions offer *--restore* on resume.
- **Chat**: `@`-mention completion, in-chat find, *Copy/Save as Markdown* and *Export as HTML*, `omp.snippets` prompt snippets, per-message timestamps, and tail-first rendering of long transcripts (last turns first, *Show earlier messages*).
- **Robustness / packaging**: shared launch/host-version code, session discovery for worktrees and Claude/Codex, `.vscodeignore` allowlist, CI + release workflows, `docs/` (publishing guide, security, contributing). Tests: unit + session-host + desktop end-to-end suites (all green).

## 0.1.0

Initial release.

- Background omp sessions per folder, hosted by a detached per-session process that survives VS Code / SSH disconnects; panels reattach after reload or reconnect.
- Sessions view grouped by project (git repository or folder) with live working / needs-input counts; flat mode via *Toggle Group by Project*.
- *New Session with Options…*: model, thinking, approval mode, plan-first / advisor / prewalk / auto-approve, goal, extra CLI flags; options persist across resumes. Goals auto-continue as in the TUI.
- Chat panel: streaming markdown with copyable code blocks, collapsible thinking, tool cards, subagent progress, omp dialogs (`ask`, select, confirm, input, editor), side questions, ANSI-colored command output, slash-command and `@file` completion, model/thinking picker, todos, queued messages.
- Extension-side commands for TUI features omp's RPC lacks: `/new`, `/resume`, `/tree`, `/fork`, `/goal`, `/btw`, `/agents`, `/changes`, `/copy`, `/cost`, `/login`, `/logout`, `/settings`, `/help`, `/exit`; `!cmd` shell commands.
- Attachments: paste/drop/pick images (sent as model images) and any other file (staged on the remote for omp's read tool).
- Links everywhere: web URLs, files with line numbers, and omp internal URLs (`artifact://`, `local://`, `skill://`, `omp://`, …).
- Diffs: line diffs with old/new numbers and word highlights in the chat, per-tool-call VS Code diffs, and a multi-file review of all session changes.
- Status bar counts, notifications on finish / needs input; stop, resume, rename, remove sessions; send editor selection to the chat.
